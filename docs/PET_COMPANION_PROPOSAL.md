# 皮皮学习宠物补充方案

状态：已进入实现。宠物功能与接口见 PET_COMPANION_API.md，实际验证与未完成项见 PET_COMPANION_VALIDATION.md；本文保留需求与设计依据，不用作完成声明。本文数值是可调的设计起点，不是已验证的儿童行为结论。

## 1. 目标与现有基础

让孩子通过教皮皮学习、获得葵花籽、照料皮皮和看到成长获得正向反馈。数学项目决定任务与知识点是否完成；本库负责宠物状态规则、动作与声音的协调、可复用的互动能力。

当前已验证基础：245 个 LFS 文件已恢复；43 项 Node 测试通过；构建、Web/微信类型检查、独立消费包检查通过。本文不据此声称新动作或微信真机体验已验收。

| 需求 | 当前情况 | 需要补充 |
| --- | --- | --- |
| 页面宠物、拖动 | 已有 Canvas 和 Web/微信输入接口 | 可配置停靠区域、页面模式；业务提供题目与按钮避让区域 |

## 2. 补充结构与边界

建议新增可选的 `PetCompanion` 层，调用已有 `PipiEngine`；原有只播放动画的接入方式继续可用。

```text
数学/识字项目：任务判定、知识点掌握、账号、葵花籽账本、云存档
                         ↓ 业务事件与确认结果
PetCompanion：成长规则、场景模式、需求、交互、反馈排队与存档适配
                         ↓ play / speak / growTo / moveTo
PipiEngine：动作计划、时钟、Canvas、素材缓存、平台适配
                         ↓
可选动作包：日常、照料、趣味、歌舞
```

拟议文件：`engine/companion/` 放协调器与纯状态规则；`engine/presets/companion/` 放台词和动作配置；工作台增加宠物事件模拟区；`assets/companion/` 放新动作母版、配置和制作记录。发布时增加可选入口，避免基础欢迎包自动包含全部素材。

拟议业务接口（不是当前可调用 API）：

```js
companion.setMode('learning');
await companion.handleEvent({
  id: 'server-event-id', type: 'knowledgeMastered',
  knowledgeId: 'make-ten', displayName: '凑十',
  confirmedGrowthPoints: 3,
});
await companion.feed({ operationId: 'unique-operation-id', count: 3 });
companion.beginBath();
companion.exportState();
```

新业务模块应分别接受 `storage`、`wallet`、`clock`、`random`、`audioCatalog` 适配器。库不凭“动画播完了”自行认定学习任务完成，也不在多个页面中各自维护独立余额。

建议存档字段：`version/revision`、累计成长点、已展示里程碑、饱足与清洁状态、状态更新时间、请求冷却时间、待恢复的照料操作。学习事件的唯一性由业务账本保障；库侧记录有界去重缓存和展示状态，避免无限增大的事件 ID 列表。

## 3. 成长与尺寸

累计成长点 G 与可花费的葵花籽分别记录。花掉葵花籽不直接撤销已掌握的知识点。

初始示例：完成有效任务 +1，首次掌握知识点 +3；同一业务事件只结算一次。重复刷题、复习与每日有效任务上限由引用项目提供规则，库只接受已确认增量。

建议身体高度采用有上限的对数曲线：

```text
r = clamp(log(1 + G / 5) / log(1 + 320 / 5), 0, 1)
bodyHeight = 58 + (104 - 58) × r
engineScale = bodyHeight / engineBaseSize
```

这里的 px 是 Canvas 逻辑像素，表示身体高度，不是整张 PNG 的高度。58、104、5、320 都应可配置。

| 累计成长点 G | 示例身体高度 |
| ---: | ---: |
| 0 | 58.0 px |
| 1 | 60.0 px |
| 3 | 63.2 px |
| 5 | 65.6 px |
| 10 | 70.1 px |
| 20 | 75.7 px |
| 40 | 82.2 px |
| 80 | 89.2 px |
| 160 | 96.5 px |
| 320 及以上 | 104.0 px |

正常增长约 1.2 秒完成，脚底锚点固定；小增量合并展示，达到里程碑再使用完整庆祝。显示区域容纳不下时，限制屏幕显示尺寸，成长存档不变。达到视觉上限后，继续累计进度，以称号或外观奖励表达后续成长。

学习事件先入账，再播放反馈。拖动、换页或关闭页面可以取消庆祝，但不得取消已确认的成长；下次初始化从存档恢复目标尺寸，避免依赖 `celebrate()` 的播放是否完成来保存成长。

## 4. 葵花籽与照料机制：原需求及建议调整

原需求包含“尽量消耗完葵花籽”“食量不足会变小”“激励坚持打卡”。这三项不能默认为已经确认的数值规则。

建议将目标设为“葵花籽有持续、可选择的用途”，给喂食、洗澡用品和可选装饰提供消费入口，不根据孩子的余额自动涨价或强制扣空。建议永久学习成长不倒退；饥饿用温和请求和待照料状态表达，余额为零时仍可抚摸、陪伴、休息。

如果产品最终保留“变小”，应把它作为单独、明确开启的体况规则：显示为暂时的体况变化，限制最大缩小比例与最低尺寸，喂食后恢复，已掌握知识和永久成长点保留。默认关闭。该选择需要产品决定，本文没有把原需求悄悄改写为已实现行为。

首轮可测试参数：一餐 3 颗籽、饱足增加 30/100；已饱时不给无效消费入口；一次请求可忽略，进入后台不堆积多条催促。具体获得/消费速度需用引用项目的任务产出数据核算，当前仓库没有这些数据，因此不承诺收支平衡。

喂食过程：选择数量 → 钱包预留或业务端幂等提交 → 显示吃籽 → 确认状态。余额不足不开始付费流程。中途动画取消不重复扣款，后台恢复根据操作 ID 对账；失败退款或保留已到账收益由钱包契约明确。不得仅在动画回调里减余额。

状态随时间变化需有单次追赶上限；长时间离线回来只给一次欢迎/照料提示，不积累债务或无限饥饿惩罚。

## 5. 场景、请求与手势

| 模式 | 自动行为 | 用户触发行为 |
| --- | --- | --- |
| `learning` 做题 | 站姿与低频眨眼；暂停闲逛、趣味音效、照料请求 | 拖动可用；反馈由题目事件或显式点击触发 |
| `home` 首页 | 在业务提供的可活动区域闲逛，带权随机，避免连续重复 | 点击/双击/抚摸；打开照料入口 |
| `care` 照料 | 只执行当前喂食或洗澡流程 | 道具交互优先，暂时禁用普通拖动 |
| `rest` 休息 | 睡觉或安静姿态 | 唤醒；不推送新的学习请求 |
| `hidden` 后台 | 暂停播放与请求 | 恢复后重新读取状态，不补播排队的趣味动作 |

优先级：销毁/后台暂停 > 用户照料与拖动 > 已确认学习奖励 > 欢迎 > 照料请求 > 随机动作。护眼提醒由业务在题目边界触发；具体时长由产品配置，库不将某个分钟数宣称为医学标准。提醒必须允许进入休息，不为播放奖励延长一次学习。

同类请求只保留一个，短时间多次知识奖励合并；请求冷却与页面切换均保留。学习页面退出后，也不立即把之前压制的请求全部播出。

手势策略需可配置：保留当前“单击 pet / 双击取消”作为兼容模式；新宠物模式允许单击从 pet/wink/nod 选取，双击从 jump/kiss 选取。双击响应必须取消待触发的单击。抚摸是按住后在身体区域短距离往返，拖动是持续位移；不要把一次拖动同时算抚摸。建议先通过显式“摸摸”照料入口验证抚摸体验，再开启自动手势识别。

## 6. 新动作制作清单

下表为拟制作动作，帧数是完整逻辑播放帧的预算，独立绘制姿态数量通常更少；最终按观感调整，不声称已经存在这些 PNG。

| 批次 | ID | 动作与分镜 | 逻辑帧预算 | 用途 |
| --- | --- | --- | ---: | --- |
| 1 | `nod` | 站姿 → 轻低头 → 抬头 → 小幅再点头 → 站姿 | 25–33 | 答对、听懂、同意 |
| 1 | `sleep` | 困倦合眼 → 头部放松 → 呼吸循环 → 睁眼回正 | 进入 16 + 循环 12 + 退出 16 | 休息、护眼结束过渡 |
| 1 | `stretch` | 下蹲蓄势 → 双翅舒展 → 停留 → 放松收翅 | 37–49 | 唤醒、休息邀请 |
| 1 | `eatSeed` | 看向籽 → 翅膀/喙接近 → 取食 → 轻咀嚼 → 满足回正 | 37–49 | 喂食闭环 |
| 1 | `bath` | 准备 → 享受涂抹 → 配合冲洗 → 抖落水珠 → 站姿 | 各段约 16–24 | 洗澡闭环 |
| 2 | `scratch` | 歪头示意 → 被挠时闭眼轻摆 → 满足回正 | 33–41 | 挠痒请求与回应 |
| 2 | `kiss` | 期待 → 轻前倾、鸟喙轻碰 → 害羞回正 | 25–33 | 双击与亲近回应 |
| 2 | `preen` | 看向翼侧 → 喙整理羽毛 → 抬头回正 | 41–49 | 日常理毛 |
| 2 | `standOneFoot` | 转移重心 → 抬单脚 → 平衡循环 → 落脚 | 进入 16 + 循环 12 + 退出 16 | 安静可爱动作 |
| 2 | `lookAround` | 眼睛看左 → 看右 → 好奇停留 → 看正 | 25–33 | 随机观察 |
| 2 | `dance` | 小踏步 → 左右摆动 → 双翅节奏 → 收尾 | 49–65 | 游戏完成、音乐互动 |
| 2 | `flap` | 双翅展开 → 原地扑翼循环 → 收翅 | 进入 16 + 循环 12 + 退出 16 | 张翅、闭翅、扑扇 |
| 3 | `sneeze` | 吸气蓄势 → 短促喷嚏 → 晃头恢复 | 25–33 | 趣味待机 |
| 3 | `hiccup` | 正常呼吸 → 轻微身体弹动 → 惊讶恢复 | 17–25 | 趣味待机 |
| 3 | `fart` | 微停顿 → 小幅姿态反应 → 害羞回正 | 21–29 | 可关闭的趣味互动 |
| 3 | `beakWipe` | 看向可交互磨嘴道具 → 左右擦喙 → 回正 | 33–41 | 磨嘴，需配套道具 |
| 组合 | `pace` | 已有走路动作走到 A，再走到 B，再停留观察 | 复用 | 来回踱步，路径由协调器编排 |
| 组合 | `sing` | 音频 + 嘴部轨道 + 可用的舞蹈/挥翅姿态 | 复用及适配 | 中英文儿歌 |

已有 `jump` 是真正跳跃；已有 `curious` 是歪头；已有 `pointLeft/pointRight` 是单翅指向，不等于双翅舒展；已有飞行扑翼不直接当作原地扑翼的合格素材。

首批先交付 nod、sleep、stretch 三个独立动作，再交付 eatSeed 与 bath 的交互分段。这样先确认角色一致性与动作流水线，再处理道具、扣款和手势的复杂流程。

### 新序列帧的质量要求

1. 严格引用 `assets/pipi-idle.png`：绿色身体、奶油色脸、蓝色大眼睛、黄色鸟喙、黄蓝翅羽、橙色脚及现有材质。保持正面镜头、光照和体型。
2. 新姿态应生成/绘制真实的关节、表情和羽毛变化。整张站姿图片的旋转、拉伸或重复帧不能替代点头、吃籽、理毛等动作。
3. 分镜先确定关键姿态，再补连续过渡；局部固定区尽量保持原像素。眼球、鸟喙与翅膀不能出现叠影、额外肢体、穿插或相邻姿态突变。
4. 统一每个动作的虚拟画布、脚底锚点和 `subjectHeight`。动作画布可加宽以容纳翼展，静态角色显示高度与原素材一致。
5. 透明 PNG，不能把棋盘格当透明背景。角色与籽、泡泡、水珠、音符等特效分层，以便复用、关特效和适配交互。
6. 一次性动作首尾与默认站姿对应；睡眠、单脚站立、洗澡等使用明确的进入/保持/退出段，自然释放，不在循环中途硬切站姿。
7. 合眼、吃籽、前倾等动作不默认叠加当前固定位置的嘴部和睁眼补丁。需增加每个动作的 `allowSpeech`/嘴部锚点等配置，或先禁用不兼容的嘴部覆盖。
8. 交付母版 PNG、分镜与来源说明、时长 JSON、引擎分页图集、清单、抽帧接触表及浏览器预览。生成接触表不能直接视为合格运行图集。
9. 使用现有 LFS 规则保存 PNG；生成文件保留哈希与制作版本。新增素材不能改写已确认旧动作的像素。

### 打包与播放扩展

现有 `assets/runtime/` 与 `assets/engine/` 格式不同。新流水线需要明确从动作母版生成引擎分页图集，不能只生成旧播放器长图或仅修改一份注册表。引擎预设清单与导出清单必须同步校验。

新日常与照料包按需加载，基础包保留当前启动素材。分页尺寸以目标平台验证为准，首轮可用不超过 2048×2048 的页做基线；单页完整 RGBA 解码约 16 MiB，因此还应通过裁边、去重和避免多页同时常驻控制峰值。PNG 下载大小不能代替解码内存测量。

当前 `SustainPlan` 可作为进入/循环/退出的基础，但需要为新动作提供可配置分段的计划构建方式。喂食与洗澡还需分段事件，不能仅靠固定总时长猜测“籽到嘴”“开始冲洗”的时间。

## 7. 洗澡与音频细节

洗澡使用身体可清洗区域的遮罩网格。香皂经过新网格时增加覆盖率，同一小区域反复滑动不会刷满整个进度；采用 Canvas 相对坐标并与缩放同步。覆盖达标后进入冲洗，再播放抖水与完成反馈。泡泡数量有上限，眼睛/鸟喙不成为必须涂抹的区域。洗澡中断可恢复或退出，清洁收益只确认一次。

首批台词配置示例：

| 场景 | 台词 | 动作 |
| --- | --- | --- |
| 欢迎 | 今天一起学点新本领吧！ | wave |
| 学习邀请 | 今天能教我数数吗？ | curious + talk |
| 掌握知识点 | 我会凑十啦，谢谢你教我！ | jump + nod |
| 长大 | 看，我又长大一点啦！ | stretch |
| 饿了 | 想吃几颗葵花籽，你愿意喂我吗？ | curious |
| 挠痒 | 脖子有点痒，可以帮我挠挠吗？ | scratch |
| 洗澡 | 一起洗个泡泡澡吧！ | bath 进入段 |
| 休息 | 我们休息一下，看看远处吧。 | stretch → sleep |
| 再次回来 | 你回来啦，我们慢慢来！ | wave |

配置包含 `id/locale/text/audioURL/gesture/cooldown`，支持静音字幕和音频失败降级。知识点名称来自业务提供的可显示文本；动态语音可由业务录音/TTS 接入，本库只播放资源。儿歌需提供可使用的曲目、实际录音和语言配置；没有音频时不把嘴部运动称为“会唱儿歌”。

## 8. 分阶段验收

第一阶段：成长与模式协调、事件去重、手势配置、nod/sleep/stretch。工作台能模拟完成任务、进入做题、休息和恢复；首批新动作可逐帧检查。

第二阶段：饱足/清洁状态、钱包与存档适配、eatSeed/bath、主动请求。示例使用明确标注的本地模拟钱包；接入项目提供真实账本。重点验证扣款幂等、取消恢复、涂抹覆盖率与照料中断。

第三阶段：日常/趣味/歌舞动作、音频资源与性能优化。待机可配置、避免连续重复；静音和做题模式不会播放趣味音效。

必须验证的行为：

- 成长曲线单调、有上限，非法/重复奖励不增加进度；新页面恢复相同成长。
- 学习模式中没有自动走动和照料催促，返回首页只恢复允许的待机。
- 单击/双击/抚摸/拖动互斥；当前旧接入行为保持兼容。
- 喂食重试、页面销毁和离线恢复不重复扣款或重复发收益。
- 后台不累计待播放动画；时钟异常和长时间离线有界处理。
- 新动作逐帧可见、锚点一致、无截断、循环连续、退出自然；深浅背景都检查透明边缘。
- 普通动作、静态嘴部补丁与新头部姿态不会发生错位覆盖。
